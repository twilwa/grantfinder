## 1) Test commands

Run everything from the repo root in `/testbed`:

- Install deps: `bun install`
- Full test suite: `bun test`
- Type checking: `bun run typecheck`
- Lint (Biome): `bunx @biomejs/biome check src/ tests/ examples/`
- Auto-format (Biome write): `bunx @biomejs/biome check --write src/ tests/ examples/`
- Usual “all checks”: `make all` (runs `make check` then `make test`)
- Static checks only: `make check` (runs `make lint` + `make typecheck`)

If debugging a single failing test, use Bun’s filtering (when available in the environment): `bun test <pattern>` and/or run a specific file under `tests/`.

## 2) Code structure

Key locations to inspect and modify:

- `src/`: primary library code.
  - Look for the OpenAI client wrapper class `X402OpenAI` and the HTTP transport/retry logic that detects `402 Payment Required`, parses payment requirements, signs with a wallet, and retries.
  - Payment policy utilities live under `src/` as well (functions like `preferNetwork`, `preferScheme`, `maxAmount` are part of the public API).
- `src/wallets/`: wallet implementations and exports.
  - `EvmWallet` (uses `@x402/evm` + `viem`) and `SvmWallet` (uses `@x402/svm` + `@solana/kit` + `@scure/base`).
- `tests/`: Bun tests validating the wrapper behavior (402 flows, selection logic, streaming, etc.).
- `examples/`: runnable usage examples; useful for reproducing issues with streaming and multi-chain selection.
- `dist/`: build artifacts (don’t edit); regenerated by build/publish steps.

## 3) Conventions

- Tooling is Bun-first. Prefer `bun` scripts and Bun test idioms over Node-only assumptions.
- Formatting/linting is enforced by Biome. Match existing import ordering, quote style, and formatting; run the Biome command before finalizing.
- Public API surface is intentionally “drop-in OpenAI”: avoid changing method names or return shapes; keep parity with `openai.OpenAI` semantics (including streaming async iterators).
- Wallet selection is policy-driven: when adding behavior, integrate with the existing policy pipeline rather than hard-coding chain/scheme preferences.

## 4) Common pitfalls

- Breaking streaming: streaming chat/completions must continue to return an async-iterable compatible with the OpenAI client expectations. When adding 402 retry logic, ensure the retry happens before the stream is consumed and that the returned object still supports `for await`.
- Mishandling 402 retries: don’t retry blindly on any 402—parse the server’s payment challenge/requirements and sign exactly what’s requested. Ensure the second request includes the correct authorization/payment headers and preserves the original request body.
- Multi-wallet ambiguity: if multiple wallets are configured, selection must respect policies (`preferNetwork`, `preferScheme`, `maxAmount`). Avoid “first wallet wins” unless the policy system already dictates that behavior.
- Editing build output: changes must be in `src/` (and possibly tests/examples). Don’t patch `dist/`.
- Skipping Biome: CI will fail on formatting/lint drift; run Biome locally in the container.

## 5) Workflow

1. Reproduce quickly: run `bun test` (or narrow to a failing file/pattern). If the issue is user-facing (README example), create a minimal reproduction in `examples/` to observe runtime behavior under Bun.
2. Locate the layer: determine whether the bug is in (a) OpenAI wrapper method surface, (b) HTTP interception/402 parsing and retry, (c) wallet signing/chain-specific logic, or (d) policy selection.
3. Patch in `src/`: keep OpenAI-compatible signatures; ensure retry logic is idempotent and doesn’t consume streams prematurely. Update wallet/policy code only through their existing abstractions.
4. Add/adjust tests in `tests/` to cover the regression (especially for 402 + retry + streaming and multi-chain selection).
5. Verify: run `make check` then `bun test` (or `make all`). Finally run Biome with `--write` if formatting changed.
